# API + LangChain4j Foundation

## Steps

1. **Add LangChain4j dependencies** ✅

- Update `build.gradle` with `langchain4j-spring-boot-starter` and `langchain4j-ollama`.  
- Keep actuator/web/validation already present.

2. **Configure Ollama properties** ✅  

- Extend `src/main/resources/application.yaml` with an `ollama` section (base URL, model).  
- Add toggles (e.g., `llm.provider=ollama`) so we can change models or endpoints if needed.

3. **Define chat API contracts** ✅  

- Create DTOs in `com.breno.llm.llm_microservice_observability_demo.chat.dto` (`ChatRequest`, `ChatResponse`, maybe `MessageDTO`) with bean validation annotations.  
- Document fields to keep the REST surface self-explanatory for workshop attendees.

4. **Wire LangChain4j services** ✅  

- Implement a config class (`ChatModelConfig`) that exposes an Ollama-backed `ChatLanguageModel` bean based on the property toggle.  
- Add a service layer (`ChatService`) that wraps LangChain4j calls, handles system prompts, and captures basic metadata (tokens, latency placeholders for future observability steps).

5. **Expose REST controller + basic tests** ✅ 

- Build `ChatController` under `chat` package: POST `/api/chat` -> validate request -> delegate to `ChatService`.  
- Add a focused slice test or integration test using `@SpringBootTest` + mocked model bean to ensure the endpoint wiring is correct now, easing future observability additions.

6. **Observability with Langfuse** ✅  

- `LangfuseChatModelListener` + `LangfuseClient` capture prompts, responses, token/cost/latency and push them to `/api/public/ingestion`.  
- Properties under `langfuse.*` (`enabled`, `base-url`, keys, environment) toggle the integration.  
- `README.md` documents how to wire the app against a manually managed Langfuse instance (cloud or local self-host) and how to enable/disable the integration.

7. **Conversation memory (🚧)**  

- Implement short-term memory using `MessageWindowChatMemory`, keyed by `conversationId`.  
- Persist the memory in Redis (local or managed instance) so multiple app instances share state.  
- Extend `/api/chat` to accept optional `memory` flags and add coverage.

8. **Essential RAG flow (🚧)**  

- Load demo documents (e.g., financing FAQ) into a local vector store (LangChain4j `EmbeddingStore`).  
- Option: reuse the same Redis/Qdrant instance chosen for memory (managed or locally installed).  
- Add a service that retrieves top-k chunks and injects them into the prompt before calling the model.  
- Provide unit/integration tests covering retrieval.  

9. **Frontend/live coding helper (🚧)**  

- Build a minimalist web client (HTML/JS or React) that hits `/api/chat` so workshop attendees see end-to-end flow.  
- optional: serve it via Spring MVC static resources or a separate Vite dev server.

10. **Environment isolation & DX (🚧)**  

- Create `docker-compose.yml` with services: Spring app, Ollama, Langfuse (+ Postgres), Redis (memory/RAG), any vector DB.  
- Add `Dockerfile` (or multi-stage) for the Spring app and document how to build/run everything via `docker compose up`.  
- Update `README.md` with quick-start instructions, environment variables, and troubleshooting tips.  
- Ensure tests can run locally (Gradle) and in container.
